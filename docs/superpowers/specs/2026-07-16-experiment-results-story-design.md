# 实验结果叙事化重写设计

## 目标

将 `docs/EXPERIMENT_RESULTS.md` 从按实验类型罗列的结果手册，重写为能够独立阅读的研究故事。读者应先理解研究矛盾、架构假设和证据链，再按需查阅详细指标与 artifact。

## 叙事主线

文档采用与 `latex/main.tex` 一致的论证顺序：

1. **表面成功的悖论：** AlgoTutorGen 与 Direct 都能显示 200/200 正确答案，但完整 Machine OK 为 198/200 与 98/200；答案正确不等于教学系统可用。
2. **约束纠缠的诊断：** Direct 从答案、加载、交互到反馈逐层流失，说明失败集中在多个义务共用同一 HTML/JavaScript 状态。
3. **完整分解链为何重要：** 非退化消融证明固定 Runtime、正确 trace 或自由 HTML 的任一单层都不足，收益来自可执行语义、契约、确定性编译和教学隔离的完整组合。
4. **边界是否真的守住：** 表示投影、semantic mutation、overlay 和 noninterference 审计分别回答语义是否跨层保持、契约是否能辨错、教学是否污染算法状态。
5. **结果能否外推：** 跨输入、跨模型和 held-out 结果说明可靠性差距在有限新条件下保留，同时暴露模型适配和未知输入的失败。
6. **诚实的负结果和代价：** Local Resume 没有显著优势，因为当前实现没有真正 checkpoint；Stage1 成本更高，超长轨迹存在体积和加载上限。
7. **结论边界：** 证据支持可执行可靠性、表示保持和有限非干扰，不支持真人学习增益、任意算法形式化正确性或 universal validator soundness。

## 文档结构

- 开篇给出一句话结论、核心矛盾和阅读路线。
- 主体每节统一使用“问题 → 关键证据 → 这说明什么 → 不能说明什么”。
- 主体只保留推动论证的核心表格。
- 视觉、教学代理指标、外部系统细节、预算、术语和完整 artifact 索引移到后半部分的“补充结果与查阅表”。
- 保留所有已审计关键数字、分母、统计检验和结果路径，不新增或删除实验事实。

## 写作风格

- 使用简体中文完整段落解释为什么要看某张表，不以术语表开场。
- 表格前先提出问题，表格后解释机制和限制。
- 避免逐条复述表格数字，只强调形成转折或支持主张的数据。
- 负结果、失败案例和 claim boundary 与正结果同等突出。
