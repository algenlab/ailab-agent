# 最终页面规格

## 1. 页面定位

最终页面不是开发者调试面板，而是面向学习者的交互式算法实验页面。

页面必须做到：

- 先帮助用户理解算法过程。
- 再展示系统为什么认为这个过程可信。
- 始终保留可追溯的校验证据。

最终页面结构：

```text
顶部任务区
左侧输入区 + 中间可视化区 + 右侧讲解区
底部语义时间线
Debug Drawer
```

## 2. 顶部任务区

目标：让用户在第一屏知道“这是什么题、输入是什么、答案是什么、系统是否可信”。

必须包含：

- 题目名称。
- 当前输入摘要。
- 当前输出。
- 解法名称和复杂度。
- 可信度状态。

可信度状态使用用户能理解的语言：

```text
代码执行通过
轨迹覆盖完整
过程转移通过校验
可视化对象绑定正确
```

禁止只展示开发者字段名，例如：

```text
artifact_ready PASS
trace_ready PASS
visual_ready PASS
```

这些字段可以放入 Debug Drawer。

## 3. 左侧输入区

目标：让用户知道系统解决的题目和当前样例输入。

必须包含：

- 题目描述。
- JSON 输入编辑器或只读 JSON 输入视图。
- expected output，如果用户提供。
- 解法选择。
- 重新生成轨迹按钮。

V1 推荐交互：

- 修改 JSON 输入后重新生成。
- 在多个 variant 之间切换。
- 对比两个解法。

约束：

- 输入编辑器不能绕过 `ProblemInput`。
- 页面重新生成必须走主 pipeline。
- 不允许前端临时改 trace 伪装成新结果。

## 4. 中间可视化区

目标：呈现算法当前步骤中最重要的数据结构和依赖关系。

必须包含：

- 主数据结构。
- 当前操作高亮。
- 依赖对象高亮。
- before / after 状态。
- 关键箭头或连接关系。

对 DP / matrix 页面，必须突出：

```text
当前格子 dp[i][j]
依赖格 dp[i-1][j]
依赖格 dp[i][j-1]
转移公式
当前计算过程
```

示例：

```text
dp[2][3] = dp[1][3] + dp[2][2]
         = 4 + 6
         = 10
```

对图搜索页面，必须突出：

- 当前节点。
- frontier / queue。
- 新访问节点。
- 当前边。
- 距离或访问状态变化。

对数组指针页面，必须突出：

- 当前窗口或搜索区间。
- 指针位置。
- 比较对象。
- 区间收缩或窗口移动原因。

## 5. 右侧讲解区

目标：把算法步骤讲清楚，把验证证据翻译成人能读懂的解释。

每一帧应该尽量包含：

- 当前阶段。
- 当前操作。
- 为什么这样做。
- 涉及哪些对象。
- 状态如何变化。
- 公式或不变量。
- 对应代码行。
- 本步校验证据。

推荐布局：

```text
当前阶段：填充内部 DP 表

当前操作：
写入 dp[2][3]

为什么这样算？
到达当前格子只能来自上方或左方，所以路径数等于两者之和。

不变量：
处理 dp[i][j] 时，它上方和左侧的格子已经被正确计算。

系统校验：
本步满足 dp[i][j] = dp[i-1][j] + dp[i][j-1]
```

约束：

- 教学解释优先显示，原始 validator 字段放在折叠区域。
- 不允许只显示自然语言而缺失状态证据。
- 不允许把 release gate 结果当作教学解释。

## 6. 底部语义时间线

目标：用户能看出当前步骤属于算法哪一段，而不是只看到帧编号。

时间线应该按语义阶段组织：

```text
初始化
填第一行 / 第一列
主循环
状态转移
返回答案
```

不同算法族可使用不同阶段：

- 二分：初始化区间、比较中点、收缩区间、返回结果。
- BFS：起点入队、弹出队首、检查邻居、首次访问、结束。
- 单调栈：扫描元素、弹出更劣候选、写入答案、入栈。
- 回溯：进入递归、做选择、记录答案、撤销选择。

最低要求：

- 能跳转到任意帧。
- 能显示当前阶段名称。
- 能区分关键帧和普通帧。

## 7. Debug Drawer

目标：保留工程证据，但不干扰学习体验。

放入 Debug Drawer 的内容：

- raw validation report。
- release gate 详情。
- trace schema 结果。
- process validator 详情。
- scene validator 详情。
- raw state JSON。
- artifact 下载入口。

约束：

- Debug Drawer 默认折叠。
- 面向学生的主页面不能依赖 Debug Drawer 才能理解当前步骤。

## 8. 必备交互

V1 最低交互：

- 上一步。
- 下一步。
- 播放 / 暂停。
- 时间线拖动。
- 查看输入。
- 查看当前状态。
- 查看校验证据。

V1 应优先新增的学习交互：

- 预测下一步：让用户填写下一个关键值。
- 点击依赖：点击对象后显示它由谁产生、影响谁。
- 修改输入：重新生成轨迹。
- 对比解法：DP vs 组合数学、BFS vs DFS 等。
- 错误注入：故意改错一个状态，让系统指出违反的不变量。
- 代码同步：当前帧高亮对应伪代码或代码行。

新增交互必须绑定 SemanticTrace、SceneGraph 或 validation report，不允许纯前端伪造教学结果。

## 9. 视觉原语到页面行为

页面应复用通用视觉原语：

当前稳定原语：

- `array + pointer`：二分、二分答案、双指针、滑动窗口、排序、快慢指针。
- `matrix / DP table`：不同路径、背包、LCS、编辑距离。
- `graph`：BFS、DFS、拓扑排序、最短路、连通分量、MST、匹配 / 网络流入门。
- `stack / queue / deque`：单调栈、单调队列、BFS frontier、滑窗候选、括号匹配、表达式求值。
- `map / hash table`：Two Sum、频次统计、前缀和计数、分组、去重。
- `tree`：二叉树、BST、LCA、树形 DP、路径和、树直径。
- `heap`：TopK、堆排序、Huffman、合并 K 路、数据流中位数。
- `trie`：前缀树插入和查询、前缀计数、Aho-Corasick 教学版。
- `union-find`：连通分量、路径压缩。
- `recursion_tree`：全排列、组合、搜索树。
- `string`：KMP、Rabin-Karp、Z Algorithm、Manacher。
- `geometry`：叉积、方向判断、凸包、扫描线、点线面。

当前可组合表达但还不是独立稳定 layout 的原语：

- `linked list`：链表反转、合并链表、快慢指针、判环、LRU 链表部分。当前可先用 `node:*`、`edge:*`、`pointer:*` 映射到 graph/tree 风格。
- `range structure`：线段树、树状数组、稀疏表。
- `math / bit`：快速幂、筛法、组合数、位掩码、lowbit、子集枚举。

新增算法时优先映射到已有视觉原语。只有出现真实的新视觉形态，才扩展 Scene Compiler 或 Web Runtime。

## 10. 页面验收标准

一个页面至少满足以下条件才可发布：

- Release gate 通过。
- HTML 可加载，无 JavaScript error。
- 第一帧、关键帧、最后一帧都有可渲染内容。
- 主数据结构在所有帧中稳定存在。
- 当前操作和依赖对象能被视觉区看见。
- 右侧说明不只是 raw JSON。
- 时间线能表示语义阶段。
- Debug Drawer 能查看完整工程证据。
