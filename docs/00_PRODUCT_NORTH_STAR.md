# AlgoLab 产品北极星

## 1. 产品一句话定义

AlgoLab 的目标是自动生成 VisuAlgo-style 的高质量交互式算法可视化页面。

输入算法题描述、样例输入和可选解法提示，系统自动生成可执行、可验证、可交互、可教学的单文件中文 HTML 页面。

更完整地说：

> AlgoLab 是一个面向算法题的可验证交互式可视化编译系统。它让 LLM 生成算法语义候选，由系统执行、校验并编译成稳定的教学页面，使算法可视化从“看起来合理”变成“过程可验证、交互可学习、结果可复现”。

## 2. 对标对象

AlgoLab 对标 VisuAlgo 的教学质量，而不是普通代码播放器。

目标页面应该像一个算法实验室：

- 有清晰的数据结构视图。
- 有逐步动画和当前操作高亮。
- 有为什么这样做的教学解释。
- 有输入修改、预测下一步、依赖点击、解法对比等学习交互。
- 有系统校验证据，能说明结果、过程和可视化绑定为什么可信。

AlgoLab 不是 Python Tutor：

- Python Tutor 关注逐行代码执行和变量栈。
- AlgoLab 关注算法语义、数据结构变化、转移依赖和教学步骤。

AlgoLab 也不是自由网页生成器：

- LLM 不直接生成 HTML/CSS/JS。
- Renderer 只消费 SceneGraph。
- 页面风格和交互由固定 Runtime 控制。

## 3. 目标用户

主要用户：

- 算法学习者：希望理解题目的状态转移、搜索过程、数据结构维护逻辑。
- 教师：希望快速得到可讲解、可互动、可复现的课堂演示页面。
- 算法题解作者：希望把文字题解变成高质量交互式可视化。

次要用户：

- 研究人员：评估 LLM 自动生成算法可视化时的正确性、过程可靠性和教学有效性。
- 开发者：扩展新算法族、新视觉原语和新校验规则。

## 4. 核心体验

用户输入：

- LeetCode 风格题目描述。
- JSON 样例输入。
- 可选 expected output。
- 可选解法思路。
- 可选用户代码。
- 希望生成的解法数量。

系统输出：

- 可执行的 `solve(input_data)`。
- 可执行的 `trace(input_data)`。
- 独立 `verify(input_data)`。
- 通过校验的 BuildArtifact JSON。
- 单文件中文交互式 HTML 页面。

页面体验：

- 看到题目、输入、输出和可信度状态。
- 看到主数据结构如何一步步变化。
- 看到当前步骤属于哪个算法阶段。
- 看到当前操作、依赖对象、转移公式和不变量。
- 可以修改输入并重新生成轨迹。
- 可以预测下一步并获得反馈。
- 可以点击依赖对象理解“为什么来自它们”。
- 可以对比多个解法。
- 可以查看过程校验证据和视觉绑定证据。

## 5. 论文级问题定义

AlgoLab 要回答的科研问题是：

> 如何让 LLM 自动生成的算法可视化，不只是好看，而是过程可验证、交互可学习、结果可复现？

系统应围绕三类错误建立防线：

- 算法结果错：`solve`、`trace.result`、`verify`、expected output 不一致。
- 过程轨迹错：步骤跳跃、状态不满足算法不变量、关键转移缺失。
- 可视化绑定错：图形对象与语义状态不对应，mark、arrow、target 指向不存在或错误对象。

对应核心贡献：

- SemanticTrace IR：用固定语义操作表达算法过程。
- Process Invariant Validator：校验过程是否符合算法族规则。
- SceneGraph Compiler：把通过校验的语义轨迹编译为统一视觉表示。
- AlgoVis-Bench：评估生成页面的正确性、稳定性和教学交互质量。

## 6. 非目标

AlgoLab V1 不做这些事：

- 不是任意 Python / JavaScript 代码调试器。
- 不是让 LLM 自由生成 HTML 的网页生成器。
- 不是每道题都手写一个专用页面。
- 不是覆盖全部 LeetCode 的通用算法求解器。
- 不是证明 LLM 对所有未知题目都正确的形式化验证系统。
- 不是生产级沙箱安全产品。

任何新功能如果要求 LLM 绕过 SemanticTrace、SceneGraph 或固定 Renderer，应默认拒绝。

## 7. V1 范围

V1 聚焦经典算法教学页面，优先覆盖以下算法族：

### 7.1 必须优先覆盖的经典算法族

- 数组基础与前缀结构：前缀和、差分数组、二维前缀和、前缀积、区间统计、原地标记。
- 数组指针：二分查找、二分答案、双指针、快慢指针、滑动窗口、区间收缩、荷兰国旗。
- 排序与选择：冒泡、选择、插入、归并、快速排序、堆排序、计数排序、桶排序、基数排序、快速选择、第 K 大 / 第 K 小。
- 栈 / 队列 / 双端队列：括号匹配、表达式求值、单调栈、单调队列、BFS 队列、滑窗最大值、循环队列。
- 哈希表与集合：Two Sum、频次统计、去重、分组、哈希映射、前缀和计数、并查前置映射。
- 链表：反转链表、合并链表、快慢指针判环、删除节点、链表相交、归并链表、LRU 基础结构。
- 字符串匹配与字符串 DP：朴素匹配、KMP、Rabin-Karp、Z Algorithm、Manacher、Trie 前缀查询、LCS、编辑距离。
- 动态规划：一维 DP、二维 DP、背包、区间 DP、树形 DP、状态压缩 DP、数位 DP、线性 DP、LIS、LCS、编辑距离、正则 / 通配符匹配。
- 贪心：区间调度、活动选择、跳跃游戏、分发糖果、合并区间、最少箭数、Huffman、局部最优交换。
- 图遍历：BFS、DFS、Flood Fill、连通分量、环检测、二分图染色、拓扑排序、课程表。
- 图最短路：Dijkstra、Bellman-Ford、Floyd-Warshall、SPFA 教学版、0-1 BFS、A* 基础演示。
- 图连通性与结构：强连通分量、割点、桥、欧拉路径、基础 Tarjan 过程。
- 最小生成树：Kruskal、Prim、并查集辅助连通。
- 网络流与匹配入门：Ford-Fulkerson / Edmonds-Karp、二分图匹配、增广路径。
- 树与二叉树：遍历、递归 DFS、层序 BFS、BST、LCA、路径和、直径、序列化、平衡性判断。
- 堆与优先队列：TopK、合并 K 路链表、数据流中位数、任务调度、Dijkstra frontier。
- Trie 与自动机入门：Trie 插入 / 查询、前缀计数、Aho-Corasick 教学版。
- 并查集：连通分量、路径压缩、按秩合并、冗余连接、岛屿数量变体。
- 回溯与搜索树：全排列、组合、子集、N 皇后、数独、括号生成、分割回文串。
- 递归与分治：归并分治、快速排序分治、汉诺塔、树递归、主定理示例。
- 位运算：异或、位掩码枚举、lowbit、子集枚举、Brian Kernighan 算法。
- 数学与数论：最大公约数、快速幂、筛法、质因数分解、组合数、模运算、扩展欧几里得入门。
- 计算几何：点、线段、叉积、方向判断、凸包、扫描线、最近点对教学版。
- 区间与高级数据结构：线段树、树状数组、稀疏表、差分约束入门。
- 缓存与设计类经典题：LRU、LFU 教学版、MinStack、队列实现栈、栈实现队列。

### 7.2 V1 收敛边界

“尽可能覆盖经典算法”不等于一次性覆盖全部题目和全部变体。V1 的覆盖策略是：

- 优先选择适合逐步可视化、适合过程校验、适合课堂讲解的经典算法。
- 每个算法族先做 3 到 10 个代表题，形成稳定视觉模式和校验模式。
- 同一算法族内复用 SemanticTrace op、target 规范和视觉原语。
- 对高级算法先做教学版，不追求竞赛级所有优化细节。
- 不为单个冷门题写专用页面。

第一阶段 benchmark 从 80 到 120 个题目样例起步；完整 V1 可以逐步扩展到 200 到 300 个经典样例，但仍以“经典算法教学覆盖”为目标，不追求全 LeetCode 覆盖。

## 8. 产品成功标准

一个生成页面只有同时满足以下条件，才算符合 AlgoLab 产品目标：

- 可执行：`solve(input_data)`、`trace(input_data)`、`verify(input_data)` 能在沙箱中运行。
- 可验证：结果一致，trace schema 合法，过程校验和 scene 校验通过。
- 可交互：页面至少支持逐步播放、阶段时间线、输入查看、状态查看和校验证据查看。
- 可教学：每个关键步骤有当前操作、为什么、不变量或公式。
- 可复现：artifact JSON、HTML、benchmark 输入和失败分类可保存和复跑。

仅仅生成一个能播放步骤的页面，不算完成产品目标。
