AlgoLab 系统流程说明

这是一份面向项目维护者的全景说明：从用户输入、LLM 生成、沙箱执行、过程校验、SceneGraph 编译，到最终 HTML 渲染和测试体系。

目标 主流程 数据结构 正确性门禁 渲染 覆盖范围 运行命令 排查问题

1. 系统目标

AlgoLab 要做什么

把 LeetCode 风格题目和具体输入转换成可验证、可逐帧播放的算法执行实验室。

用户看到的是步骤、状态、代码、高亮、依赖关系和校验证据。

AlgoLab 不做什么

不让 LLM 直接写网页，不为每道题硬写 renderer，不把“页面看起来对”当作算法正确。

所有页面都来自固定 runtime，算法过程必须先通过机器校验。

核心边界：LLM 生成 solve / trace / verify 候选；系统负责执行、验证和修复；renderer 只消费通过校验的 SceneGraph。

  -> 重新执行 solve / trace / verify
  -> 重新走所有校验

3. 核心数据结构

ProblemInput

用户请求。包括题目、输入 JSON、expected、思路、用户代码和解法数量。

algolab/schemas/input.py

SemanticTrace

算法运行过程。由固定 op 和状态快照组成，是校验和渲染的关键中间层。

algolab/schemas/semantic_trace.py

SceneGraph

页面运行时的输入。包含 frame、object、mark、state、teaching 和 evidence。

algolab/schemas/scene_graph.py

BuildArtifact

最终构建产物。保存 variants、scenes、validation、contract、visual plan 和 render report。

algolab/schemas/validation.py

CorrectnessContract

可选正确性契约。描述输入输出 schema、postcondition、oracle 和测试样例。

algolab/schemas/correctness.py

VisualPlan

可选视觉计划。只能选择高层表现策略，不能改变算法结果或 trace。

algolab/schemas/visual_plan.py

SemanticTrace 事件示例

{
  "step": 3,
  "op": "set",
  "targets": [{"id": "dp[1][3]"}],
  "deps": [{"id": "dp[0][3]"}, {"id": "dp[1][2]"}],
  "role": "current",
  "reason": "当前位置只能从上方或左侧到达。",
  "state": {"dp": [[1,1,1,1], [1,2,3,4]], "i": 1, "j": 3},
  "code_line": 4
}

4. 正确性门禁

层级 负责内容 代码位置
执行一致性 solve == trace.result，expected 一致，verifier 一致，多解法一致。 pipeline.py
Contract 输入输出 schema、postconditions、oracle、test cases。 verification/contract_validator.py
Trace schema 固定 op、连续 step、target 可解析、输入输出一致。 verification/trace_validator.py
Process invariant 防止过程乱写：DP 转移、BFS 距离、二分窗口、堆、并查集、KMP、LCS 等。 verification/process_validator.py
Scene frame 可渲染，mark/arrow 指向存在对象。 verification/scene_validator.py
Release gate 只有 artifact、trace、process、visual 都 ready 且无错误才发布。 verification/release_gate.py

逐帧要求

小规模 DP 表更新单元不超过 80 时必须逐帧展示。以 LeetCode 62 不同路径 m=3,n=7 为例，内部 12 个格子都必须有独立 set dp[i][j] 事件，不能只展示前几步然后直接跳到最终格。

5. 渲染系统

稳定模式

面向教学验证，展示状态、代码、步骤、证据和交互问题。

algolab/renderer/export.py

创意模式

只消费已通过校验的 artifact，提供更强视觉表现，不参与正确性判定。

algolab/renderer/creative.py

Renderer 的输入边界

SemanticTrace
  -> scene_compiler.compile_scene()
  -> SceneGraph
  -> renderer/export.py
  -> 单文件 HTML

Renderer 不读取 LLM 原始 prompt，不运行算法代码，也不负责判断答案是否正确。

6. 支持的视觉形态

array + pointer matrix / DP table graph stack queue / deque map / hash table tree heap trie union-find recursion tree string geometry ML primitives
算法族 代表样例 主要风险
DP打家劫舍、不同路径、背包、LCS、编辑距离大表格可读性、逐帧密度
图BFS、DFS、拓扑、Dijkstra、MST大图布局和边状态编码
栈队列每日温度、BFS 队列、滑动窗口弹出原因和候选区间解释
树结构BST、LCA、Trie、Heap、Union-Find复杂树的空间布局
搜索全排列、组合、回溯树搜索树爆炸，需要裁剪
几何凸包、扫描线坐标缩放、遮挡、密集线段

8. 常见排查

页面步骤太少

先查 trace 事件数。多数情况下不是前端跳帧，而是 trace(input_data) 生成得太稀疏。

python - <<'PY'
import json
from pathlib import Path
data = json.loads(Path("output/algolab.json").read_text())
for v in data["variants"]:
    print(v["name"], len(v["trace"]["events"]))
PY

Gradio 缓存权限

本项目在 app.py 中设置了 GRADIO_TEMP_DIR=.gradio_cache，避免写入 /tmp/gradio。

chmod -R u+rwX,g+rwX .gradio_cache

动态页面和静态 dashboard

  • Gradio 页面会调用 LLM，是动态生成入口。
  • output/dashboard/index.html 是静态 dashboard，不需要 LLM，也不需要 Gradio。
