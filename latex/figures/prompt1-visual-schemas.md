## Figure B: Detailed System Architecture

---BEGIN PROMPT---

[Style & Meta-Instructions]
High-fidelity scientific schematic, technical vector illustration, clean white background, distinct boundaries, academic textbook style. High resolution 4k, strictly 2D flat design. Use a precise Visio/Illustrator aesthetic with thin charcoal outlines, soft pastel fills, consistent icon geometry, and generous white space. No tables, no shadows, no gradients, no photorealism, no decorative people.

[LAYOUT CONFIGURATION]
* **Selected Layout**: Linear pipeline combined with a parallel lower teaching stream and one cyclic repair loop.
* **Composition Logic**: A wide landscape canvas with a left input dock, a dominant upper algorithmic pipeline, a slim validation rail directly beneath it, a lower purple teaching stream, and a single red repair arc across the top.
* **Color Palette**: Navy #2F5D8A and azure #DCEEFF for canonical algorithmic flow; teal #3F8F83 and mint #DFF3EC for deterministic validated stages; purple #7456A8 and lavender #EEE8F8 for pedagogy; muted red #D96C5F and pale red #FBE9E6 for failure and repair; slate #68727E and light grey #F3F5F7 for validation.

[ZONE 1: FAR LEFT - INPUT DOCK]
* **Container**: A compact vertical rack with four offset document cards inside a light-grey rounded panel.
* **Visual Structure**: Each card has a distinct small icon: question mark on a document, numeric brackets, checkmark oracle badge, and code brackets. The four cards merge through a funnel arrow into the first pipeline module.
* **Key Text Labels**: "Problem q", "Input i", "Oracle e", "Optional code c"

[ZONE 2: UPPER CENTER - CANONICAL ALGORITHMIC PIPELINE]
* **Container**: A long horizontal white band occupying most of the canvas width.
* **Visual Structure**: Arrange exactly five large stages left to right with uniform spacing. Stage one is a blue code document. Stage two is a teal compound sandbox container with a shield and gear; inside it, show a small TraceSession timeline and an output ribbon for the semantic trace. Stage three is a teal compound compiler container; inside it, show a node-and-edge graph and an output ribbon for the validated scene graph. Stage four is a blue browser window representing the fixed runtime. Stage five is a mint monitor showing the released interactive page. Place exactly four diamond contract gates: C_S between stage one and stage two, C_T between stage two and stage three, C_G between stage three and stage four, and C_B between stage four and stage five. Do not add any other diamond gate and do not duplicate a contract label. Above the band, draw a thin solid navy guide line with a shield badge.
* **Key Text Labels**: "LLM Spec", "Sandboxed Materialization", "TraceSession", "SemanticTrace", "SceneGraph Compiler", "Validated SceneGraph", "Fixed Web Runtime", "Browser Artifact", "C_S", "C_T", "C_G", "C_B", "Canonical algorithmic state"

[ZONE 3: CENTER LOWER RAIL - VALIDATION CHECKS]
* **Container**: A slim light-grey rail aligned directly below the corresponding upper pipeline modules.
* **Visual Structure**: Place six small shield-shaped check badges along the rail. Each badge contains a concrete checkmark icon and aligns vertically with the boundary it validates. Connect adjacent badges with a thin slate line so the rail reads as continuous verification coverage rather than a second data pipeline.
* **Key Text Labels**: "Result", "Trace", "Process", "Scene", "Projection", "Release"

[ZONE 4: LOWER CENTER - PEDAGOGICAL STREAM]
* **Container**: A separate lavender rounded band below the validation rail, starting under the scene-graph module and ending at the browser artifact.
* **Visual Structure**: From the scene graph, a dashed purple line descends into a funnel-shaped sanitizer with a lock symbol. It continues into a lavender teaching card containing a lightbulb, speech bubble, and learning-log icon, then rises into the final browser artifact. Keep this stream visually separate from the solid navy algorithmic pipeline.
* **Key Text Labels**: "Read-only facts", "Overlay sanitizer", "Teaching enrichment", "Pedagogical state"

[ZONE 5: TOP ARC - IMPLEMENTED REPAIR BOUNDARY]
* **Container**: An open white region above the main pipeline reserved for one large curved repair path.
* **Visual Structure**: A muted-red curved arrow begins at the release audit beside the browser artifact, travels left across the top, enters a compact wrench-and-document repair node, and returns to the first LLM specification module. Beneath the arc, add one small paired-arrow icon indicating that downstream materialization and teaching run again. Do not draw independent repair arrows to trace, scene, runtime, or teaching modules.
* **Key Text Labels**: "Failure signal", "Repair spec", "Recompute downstream", "Not fully checkpointed"

[CONNECTIONS]
1. Four input cards in Zone 1 merge into the LLM specification module in Zone 2.
2. Solid navy arrows connect exactly five stages in Zone 2 from left to right through exactly four diamond contract gates in this order: C_S, C_T, C_G, C_B.
3. Thin vertical slate connectors associate each validation badge in Zone 3 with its corresponding module or boundary in Zone 2.
4. A dashed purple arrow branches from the Validated SceneGraph output inside stage three to the sanitizer funnel, teaching card, and Browser Artifact.
5. One large muted-red curved arrow loops from the Release badge back through the Repair spec node to the LLM Spec module.
6. No arrow bypasses validation and no repair arrow targets an independently checkpointed downstream module.
